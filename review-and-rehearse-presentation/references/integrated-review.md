# Integrated review

## Argument first

Read the argument as plain text, ignoring the design. Its relevance, prerequisites, transitions and close should all serve the outcome. For each scene, name the audience task and check that everything the task needs is on screen together.

## Checks

| Check | Passes when |
| --- | --- |
| Evidence | Values, units, denominators, quotations and causal wording match the sources, and you have recomputed the comparisons. |
| Qualification | Claims on screen carry their scope without relying on notes. |
| Perception | Essential labels, strokes and screenshot details are legible at the size the audience sees. |
| Interpretation | Viewers can compare or trace the relationships; scales and arrow meanings are consistent. |
| Action | The audience can use the intended understanding, decision or next step. |
| Coordination | Speech adds to the visuals, with time to read and earlier states kept where needed. |
| Access and distribution | Notes, captions, alternatives, reading order, media and static exports survive delivery. |
| Voice | The deck follows the user’s preferences and the editorial rules, and keeps useful expression and technical detail. |

A slide that looks clean, passes a contrast check or reads quickly at a glance may still not be understood. Apply an external standard only when the request calls for it, and check its current official criteria when exact conformance matters.

## Testing understanding

1. Choose a concrete task from the brief: compare the alternatives, trace the mechanism, explain a limitation or say what could change the recommendation.
2. Write down the evidence or reasoning an adequate answer contains.
3. If a fresh reviewer is available, have them do the task before they see the intended answer. Record their answer and any misunderstanding.
4. If you simulate the reviewer yourself, label the result as a simulation. It is not evidence of human understanding.

Explaining it straight away, applying it to a new case, remembering it later and using it at work are four different results. Liking the talk is none of them.

## Findings and rechecks

- Locate each finding by slide and reveal state, or by timestamp.
- Use severity to rank findings. A false claim stays a failure however good the rest is.
- After a repair, recheck the claim against its source, the changed exports, the transitions and any variant affected.
- Say so when a suspected issue is still unverified.
