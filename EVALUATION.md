# Evaluating presentation skills

This is a maintainer protocol for testing changes to the skills. It is separate from normal presentation work and does not add a runtime prerequisite. These cases specify evaluations to prepare; they are not a completed benchmark or evidence of effectiveness.

Compare three conditions:

- **Baseline:** the model and necessary authoring/rendering tools without these presentation skills.
- **Current:** the same setup with the current skill packages.
- **Candidate:** the same setup with the proposed revision.

Use the same source packets, user requests, output formats, model/version, tool permissions and resource allowance. Start each run clean. The baseline must not receive these skills through ambient instructions, descriptions, references or prior conversation. Record overlapping guidance supplied by production tools. Compare within a model/platform before combining results across platforms.

Retain source packets and exact prompts. Use invented or publishable material with independently checked expected values. Preserve a snapshot or hash of each skill version. Run more than one generation per condition where practical; two is an exploratory start, not a claim of statistical reliability. Reserve unseen cases for checking revisions.

| Case | Fixture and request | Observable checks |
| --- | --- | --- |
| High-level outline | Mixed source notes; ask for a concise section flow only, with a known audience and duration. | Relevant section purposes and coherent sequence; no imposed slide count, full storyboard or slide production. |
| Saved-project handoff | Give a fresh agent only a working brief, source notes and a request to continue with an outline. Then change one consequential audience or evidence detail. | Continues from saved material without repeating settled intake; preserves source qualifications, updates the existing record and identifies affected work. No unrequested stages or empty files. |
| Decision briefing | Alternatives with different costs, a component improvement, a smaller whole-process gain, incomplete evidence and a consequential exception. | Correct values and comparisons; appropriate qualifications; no invented winner. A reviewer can identify the tradeoff and what could change the recommendation. Use values different from the bundled timing example. |
| Technical explanation | An unfamiliar mechanism with a whole-system view, detailed component and worked case; specify mixed expertise. | A newcomer can trace a new case; an expert can inspect assumptions. Labels, connection meanings and whole/detail correspondence survive. |
| Crowded-slide repair | A real rendered fixture with useful detail, a deliberate expressive choice and a strong template requirement; request one bounded repair. | The requested repair improves use at realistic scale while evidence, voice, template and editability survive. Recurring labels are judged by function. |
| Live-to-reading conversion | A deck with reveal states, notes and an evidence claim; request a usable reading export. | The static output is complete, explanations are accessible and qualifications survive. A reader can reconstruct the rationale without narration. |
| Rehearsal review | An overlong synchronised recording and a transcript-only variant with the same planned content. | Recording findings match timestamps. Transcript-only findings respect the available evidence. Proposed cuts address scope; estimated time savings remain labelled. |

Include findings, questions and artefact labels in the fixtures so title selection is tested across different tasks. Include an uncertain visual approach to test early rendering and an established design to check that the revision adds no unnecessary exploration. Inspect each delivered format, including native editability where requested.

Conceal the generating condition from reviewers and vary review order. Review actual artifacts, with source packets available for evidence checks. Keep these dimensions separate:

- **Integrity:** correct claims, calculations, quotations, scope and qualifications.
- **Communication:** the intended audience can perform the specified task with adequate reasoning.
- **Visual and delivery fitness:** readable essentials, useful representation, coherent sequence, usable exports and checks appropriate to the medium.
- **Voice and preference fit:** requested conventions and worthwhile expression survive.
- **Effort:** time, tool/model use, user interruptions, repair cycles and manual correction.

Invented evidence, materially misleading claims and unreadable essential content remain explicit failures; visual appeal cannot offset them. Human task results, agent reviews and mechanical checks are different evidence. Record which was used. A successful agent answer does not establish human comprehension, and immediate understanding does not establish retention or workplace use.

For each run, retain the exact prompt, source/version identifiers, generated sources, renders and exports, checks performed, findings and resource use. Label estimates and untested conditions. Compare the candidate against both current skills and baseline. Keep changes that repeatedly improve relevant outcomes without introducing material regressions or disproportionate effort; revise or remove changes whose benefit is not demonstrated. Any optional independent-review experiment should account for its additional model calls and time.

Use recurring failures to select a small set of original, rendered before/after examples for future references. Record the audience task and why a change helps. Include different valid visual styles, preserve meaningful complexity and expression, and keep examples distinct from universal templates.

For the optional `grill-presentation` companion, test explicit invocation separately from interview quality. Use a vague brief with a consequential conflict, a settled brief ready for the next task, and an existing artifact that warrants bounded companion help. Check that questions follow dependencies, available facts are investigated, uncertainty stays honest, and the interview stops at readiness. Repeat with the companion skills absent: the interview must remain usable. Verify that ordinary briefing does not activate grilling, and that companion calls preserve scope and settled answers. Host invocation controls require checks in each supported client.
