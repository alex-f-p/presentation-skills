# Grill a presentation

Run only when the user explicitly asks for this interview. Challenge the choices about audience, outcome, evidence and scope that would change the presentation. Keep the working brief in the conversation unless the user names another place.

1. Read the supplied context, sources and existing material. Keep settled choices, and separate facts, assumptions and decisions. Look up any fact you can reach; do not ask the user to repeat it.
2. Map the unresolved decisions and what each depends on. Ask a small round of related questions whose prerequisites are settled, then wait. Use the [questioning guidance](references/questioning.md) to choose branches and expose contradictions.
3. Let the answers set the next round. Press weak reasoning and conflicting priorities. Recommend when you have grounds, giving the reasons and tradeoffs. Accept disagreement and uncertainty; the user agreeing with an assumption does not make it evidence.
4. When talk cannot settle a question, pick one: a short investigation, a stated assumption, a narrower claim or a concrete sample. For existing material, samples or a next stage the user has asked for, use the [related-skills guide](references/related-skills.md). Fold the result into the brief and reopen only the questions it affects.
5. Stop when another agent could do the next requested task without inventing the audience, outcome, central question or claim, evidence status, scope or delivery conditions. Resolve each contradiction or state how it is bounded, and record remaining work. If the user asks to stop, stop and state the assumptions that matter.

Return a concise brief: decisions, constraints, exclusions and open work, in the user’s voice and preferences. An interview-only request ends with the brief. Go on to creation only if the user asked, and never pause for approval between stages.
