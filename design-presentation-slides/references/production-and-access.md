# Production and access

## Format and files

- Follow the authoring and rendering instructions for the requested format. Never invent an API or quietly switch formats.
- A request for editable native objects is not met by a PDF, an HTML page or a slide-sized image.
- Use original assets where fidelity matters.
- If a needed capability is missing, say so and offer an alternative, labelled as an alternative.
- Keep sources and deliverables in the project location, and intermediate files apart from them.
- Check a source’s permissions before uploading it to any service.

## Access

Build in:

- readable detail, defined terms and accessible supporting text;
- synchronised captions for video with meaningful audio, checked for accuracy, timing and essential non-speech sound;
- transcripts for recorded audio. A video transcript is a reading alternative; it does not replace captions;
- descriptions of essential visuals the audio does not convey.

Check in the rendered output:

- meaning that survives without colour, plus contrast, line weight, glyphs and reading direction;
- nothing essential hidden by overlays such as captions;
- reading order, text alternatives, meaningful link text and media.

Passing a contrast check does not show that a slide is accessible, or legible when projected. For exact conformance questions, use the current [WCAG guidance](https://www.w3.org/WAI/standards-guidelines/wcag/); [WAI presentation guidance](https://www.w3.org/WAI/teach-advocate/accessible-presentations/) covers delivery and materials.

## Variants

Produce the versions the request needs. A reading version must carry what the speaker would have said. Confirm recipients receive notes or supporting explanation they can use.

## Inspection

1. Look at an overview for sequence.
2. Look at each affected slide for collisions, clipping, missing assets, font substitution and essential small text.
3. Open each requested export and check values, qualifications, notes, links, media and reveal states.
4. After repairs, re-render and inspect what changed and every variant it affects.
5. Test on the real projector or in a small remote window where you can, and say which.

A layout that passes a geometry check can still be misread, so read each slide as the audience would. Report a render check as a render check: venue, assistive-technology, rehearsal and audience tests are separate. If rendering fails, make a few attempts to fix it, then report the check as blocked and the output as unverified.
